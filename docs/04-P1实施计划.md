## 一、P1 要解决什么

一句话：**把你明确指定的文件，变成一条条可追溯、可增量更新、可重建的档案记录。**

P1 **不做**检索（P2），**不做**生成（P4），**不做**历史对话（P3）。它只做「进来」和「记住进来过」。

---

## 二、范围与硬约束

| 约束 | 具体含义 |
|---|---|
| 只处理你指定的文件 | 首次运行只吃 `brain.config.json` 里 `roots` 明确列出的路径，或命令行显式给出的路径。**不扫描整机。** |
| 原始文件只读 | 打开方式一律 `rb` / 只读。不移动、不改名、不删除、不改 mtime。 |
| 不联网 | 除解析本地文件外不发任何请求。 |
| 不改环境 | 不写注册表、不装依赖、不建计划任务。 |
| 数据全在项目内 | 只写 `recallos/` 下的 `data/`、`index/`、`state/`、`cache/`。 |

## 三、格式支持与验证策略

| 格式 | 解析方式 | 依赖 | 验证方式 |
|---|---|---|---|
| Markdown `.md` | 按标题分级，每个段落带 `heading_path` | 无 | 合成课件笔记，断言章节路径正确 |
| TXT `.txt` | 按空行分段，编码依次尝试 utf-8-sig / utf-8 / gb18030 / big5 | 无 | 用 GBK 和 UTF-8 两个文件验证编码回退 |
| Word `.docx` | `zipfile` + `xml.etree`（OOXML 本质是 zip） | **无** | 真实 `.docx` 抽样 |
| PPT `.pptx` | `zipfile` + `xml.etree`，按 `slideN.xml` 数字序 | **无** | 真实 `.pptx` 抽样，断言页序不乱 |
| Excel `.xlsx` | `openpyxl`（已装） | 已存在 | 真实表格抽样 |
| **PDF** | `pypdf`（已装）；若装了 PyMuPDF 则优先 | 已装 | **单独验证**：① 有文字层的 PDF 能抽出文本；② 扫描件（无文字层）报明确错误并建议走 OCR，**不算崩溃** |

**PDF 单独验证的原因**：它是唯一一个「解析失败是常态」的格式——大量 PDF 是扫描件。P1 必须把「抽不出文字」和「文件坏了」区分开，给出不同状态。

## 四、数据契约

### 4.1 一份资料的档案字段

| 字段 | 说明 | 要求 |
|---|---|---|
| `doc_id` | 稳定 ID | **由 `(来源类型, 绝对路径)` 派生**，不用自增、不含时间。同一文件永远同一个 ID |
| `source_ref` | 原始路径 | 绝对路径，原样保存，只读 |
| `content_hash` | 抽取后正文的 sha256 | 判断「内容是否变了」 |
| `doc_hash` | 同上，用于跨路径查重 | 同内容不同位置 → 识别为副本 |
| `format` / `extractor` | 格式与抽取器标识 | 例 `docx` / `pdf:pypdf` |
| `imported_at` | 首次导入时间 | 不变 |
| `updated_at` | 最近一次状态变更时间 | 变 |
| `status` | 处理状态 | `indexed` / `duplicate` / `pending` / `failed` |
| `mtime` / `size` | 文件指纹 | 增量短路用 |
| `error` | 失败原因 | 仅 `failed` 时有值，**必须非空** |

### 4.2 状态机

```
        首次见到
           │
           ▼
      [解析中] ──失败──► failed（记录原因，不重试、不静默跳过）
           │
        成功
           ▼
       indexed ◄──────── 内容变化 → 重新解析 → 更新（清空旧 chunk 再写新的）
           │
   与他人内容完全相同
           ▼
      duplicate（保留档案，指向正本，不重复存正文）
```

### 4.3 目录与文件

```
recallos/
├─ data/docs/<doc_id>.json     每份资料一个可读档案（元数据，不含正文）
├─ cache/<doc_id>.txt          抽取出的正文（可删，可重抽）
├─ index/recall.db             派生索引（可删，可重建）
└─ state/
   ├─ sources.json             权威来源清单 ← 重建的唯一依据
   └─ imports.jsonl            只追加的导入流水（只记状态变化，不记 skip）
```

**为什么 `sources.json` 是权威**：`index/` 删掉后，必须还能知道「原本有哪些来源」。这份清单小、可读、可手工修。

## 五、必须满足的行为与对应验收测试

每条都是**可机器断言**的，断言对象是磁盘上的文件与数据库里的行。

| # | 行为 | 验收测试 |
|---|---|---|
| B1 | 只处理指定文件 | 给一个目录 → 只索引白名单扩展名；给单个文件 → 只索引那一个 |
| B2 | 原始文件只读 | 导入前后比对：路径、大小、mtime、前 64KB 字节完全一致 |
| B3 | 稳定 ID | 同一文件导入两次，`doc_id` 完全相同；把文件整体复制到别处，两个 `doc_id` 不同但 `doc_hash` 相同 |
| B4 | 重复导入不产生重复档案 | 第二次导入 → `doc` 行数不变，`chunk` 行数不变，`sources.json` 条数不变 |
| B5 | 内容变化 = 更新，不是覆盖 | 改一个文件加一段 → 只有它的 `content_hash` 变化，`imported_at` 不变，`updated_at` 变，旧 `chunk` 已被替换（chunk 行数与内容都反映新正文） |
| B6 | 失败必须记录原因 | 造一个损坏的 `.docx`（改坏 zip 头）→ 该文件 `status='failed'` 且 `error` 非空且能在 `imports.jsonl` 里找到；**其他文件仍然全部成功** |
| B7 | 索引可从档案重建 | 备份 `chunk` 表的全部 `chunk_id` → 删掉整个 `index/` → `index --rebuild` → `chunk_id` 集合**逐字节相等** |
| B8 | 无文字层 PDF 不崩溃 | 扫描件 PDF → `failed`，`error` 含 `OCR` 提示，退出码仍为 0（不是异常） |
| B9 | 增量：第三方文件不动则不重解析 | 第二次运行 → 全部 `skipped`，`chunks_added == 0` |
| B10 | 来源消失被如实报告 | 删掉一个已登记文件 → `index --rebuild` 报 `missing` 并从 `sources.json` 移除 |
| B11 | 空目录 / 不存在路径 | 退出码非 0，stderr 有可读消息，无 traceback |
| B12 | 端到端闭环 | 导入 → 关进程 → 新进程打开 → 同一 `doc_id`、同一 `chunk_id` 集合可读回 |

## 六、实现顺序

**每一步都以「可运行 + 可验证」为完成标准，做完一步停下来报告。**

### 第 1 步：身份与指纹（0.5 天）
- `brain/core/ids.py` — 由来源派生 `doc_id` / `chunk_id`（纯函数，不碰磁盘）
- `brain/core/hashing.py` — 三级指纹：`mtime+size` → 文件 sha256 → 切片 sha256
- `brain/core/source.py` — 来源引用 + 统一来源定位符 `doc:<id>#chunk=<n>`
- **完成标准**：单元测试证明「同样的输入永远得到同样的 ID」，且 ID 不含时间、不含自增

### 第 2 步：解析器契约 + 无依赖格式（1 天）
- `brain/ingest/base.py` — `ParsedDoc` / `Segment` / `ParseError` / 扩展名注册表
- `brain/ingest/textual.py` — Markdown（带标题路径）、TXT（含编码回退）
- **完成标准**：任意文本都不抛未捕获异常；`.md` 的 `heading_path` 正确；GBK 与 UTF-8 文件都能读出中文

### 第 3 步：Office 三种格式（1 天）

- **完成标准**：三类真实文件都能抽出正文；**不新增任何第三方依赖**（DOCX/PPTX 走 stdlib）；损坏文件抛 `ParseError` 而非崩溃

## 七、回滚方案

P1 全程只**新增**文件，且所有产物都在四个目录里，删除即回滚：

```powershell
# 回到 P0 状态（索引、档案、状态全清，源码不动）
Remove-Item -Recurse -Force recallos\index, recallos\data\docs, recallos\cache
Remove-Item -Force recallos\state\sources.json, recallos\state\imports.jsonl
python recallos\bin\recall.py init
python recallos\bin\recall.py doctor
```

用户的原始文件**从不参与回滚**，因为从未被修改。
