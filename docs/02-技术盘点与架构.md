## 2. 可行性与风险评估

### 2.1 需求 → 可行性映射

| 需求 | 可行性 | 说明 |
|---|---|---|
| 个人记忆系统 | ✅ 可做 | 但**不要**基于 `@fooxe/dsh-memory` 做核心（它只做子串匹配、无来源定位、无版本管理，且有 §9.2 的 bug）。插件保留作"系统提示注入通道" |
| 跨会话找回历史讨论 | ✅ 可做 | DSH 已把完整对话落在本地（v4 jsonl 事件流），这是本项目最被低估的资产 |
| 多格式资料管理 | ✅ 大部分可做 | MD/TXT/HTML/DOCX/PPTX/XLSX 零新增依赖；PDF 需装一个解析库 |
| 知识复用引擎 | ✅ 可做，但有不确定性 | 最大风险是**召回质量**（无 embedding）。缓解见 §3 |
| 冲突发现 | ⚠️ 高风险高价值 | 需要"断言级"数据模型而非文档级，建议放 P5 之后 |
| 防重复导入 | ✅ 已验证 | `content_hash` + `source_path` 唯一约束实测生效 |
| 不每次全量重扫 | ✅ 可做 | mtime+size+hash 三级短路 + 增量 FTS 对账 |
| 不动原文件 | ✅ 明确纳入设计 | 源文件只读，产物全在独立目录 |

### 2.2 风险登记表

| 风险 | 等级 | 缓解措施 |
|---|---|---|
| 无 Embedding，纯词法召回率受限 | 高 | 两阶段检索：BM25 召回 top-40 → Agent 本体重排；主题标签做第二路召回。把"模型即语义层"当设计而非缺陷 |
| 中文 trigram 最低 3 字 | 中 | 已实测的 unigram 空格切分兜底通道，2 字词也能命中 |
| 上下文预算被无关资料挤爆 | 高 | 硬预算：默认只回 snippet（≤240 字）+ top-K，同 doc ≤3 chunk，总量 ≤2500 token；`--deep` 才取全文 |
| WPS 端本地 FS / 持久化假设不成立 | 高 | core 零宿主依赖 + 存储适配器接口 + 权威数据纯文本；SQLite 索引可重建 |
| 依赖安装受注册表代理干扰 | 中 | 已验证 curl 直连 + 离线 wheel 流程（§9.3） |
| `memory_search` 对 user scope 失效 | 中 | 自建 FTS 索引直接读同一批 Markdown；插件只当注入通道 |
| 定时任务与桌面实例争用锁 | 中 | 单写者 + 文件锁 + WAL；索引写入只发生在显式命令里，不做常驻进程 |
| LibreOffice 缺失 | 低 | 纯文本抽取不需要；只影响"Office → 页面图 → OCR"支线 |
| 资料含隐私内容 | 中 | 目录白名单 + 敏感目录黑名单 + 只读原则 + 不入公开仓库 |

### 2.3 明确不做的事（以及升级触发条件）

**不引入向量数据库。** 升级条件（满足任一）：
- "确认答案在库中但词法召回失败"的案例 > 20%，且 LLM 重排无法挽回
- 语料规模 > 10 万 chunk

**不建知识图谱。** 升级条件：
- 人工确认过的实体关系 > 500 条，且真实出现多跳推理需求

**不起常驻服务。** MVP 全部是 CLI 单次调用。

## 3. 推荐技术架构

### 3.1 三条核心取舍

1. **Python + SQLite(FTS5) + Markdown/JSON。** 不加运行时、不加服务、不加第三方检索库。实测证明 FTS5 的中文检索与 BM25 排序够用。
2. **Agent 本体就是语义层。** 检索分两阶段：阶段一只返回 id/标题/snippet 的候选表（便宜）；阶段二由 Agent 读候选、判断相关性、决定深读哪几篇。
3. **权威层与索引层物理分离。** `data/` 是可读可改可迁移的纯文本（权威）；`index/recall.db` 是可丢弃的派生索引（随时重建）。

### 3.2 数据流

```
资料源（只读）
  文件 / 网页 / 视频稿 / 会话转录 / 手写笔记
        │
        ▼
  Ingestion ── 解析 · 指纹 · 切片
        │
        ▼
  data/ 权威层（Markdown + JSON）  ◄──────────────┐
        │                                          │
        ├──► index/recall.db（FTS5 派生索引）      │
        │            │                             │
        └──► Memory Core（画像/项目/决策/会话摘要）─┤
                     │                             │
  当前任务 ──► Retrieval（BM25 召回 → 过滤 → 候选表）
                     │         ▲
                     │         └── index/recall.db
                     ▼
             Context 组装（snippet 分级 · token 预算）
                     │         ▲
                     │         └── data/ 权威层
                     ▼
             Agent 本体（重排 · 判断 · 生成）
                     │
                     ▼
             outputs/ 成果（每份带 sources 段）─────┘
                     ▲
  Maintenance（去重 · 失效 · 冲突）──► 权威层
```

### 3.3 模块契约

| 模块 | 输入 → 输出 | 持久化 | 失败处理 |
|---|---|---|---|
| **A** Memory Core | 会话摘要 / 用户陈述 / 成果 → 记忆卡片 | `data/memories/` `projects/` `decisions/` | 写入前先检索同题；命中走 merge 而非 create |
| **B** Ingestion | 文件 / URL / 文本 → doc + chunk | `data/docs/*.json` + `cache/` | 单份失败只标 `failed`，绝不中断整批 |
| **C** Knowledge Index | chunk → FTS 行 | `index/recall.db` | 损坏即整库重建，从权威层重放 |
| **D** Retrieval & Context | 查询 → 候选表 + 预算内上下文 | 无（只读） | 召回为空如实返回空，绝不编造 |
| **E** Reuse Engine | 需求 + 上下文 → 成果 | `data/outputs/` | 来源缺失时降级为"未溯源结论"并显式标注 |
| **F** Maintenance | 全库 → 去重/失效/冲突报告 | 报告 + 状态字段 | 只建议不自动删，人工确认后生效 |
| **G** Source Tracking | 各处 → 统一定位符 | 内嵌于 doc / chunk / output | 定位符失效报 orphan，不静默退化 |
| **H** User Control | 用户指令 → 查看/改/删 | 直接改权威层 | 删除走软删 + 修订历史，可恢复 |

### 3.4 统一定位符（Source Tracking 的核心）

```
doc:<doc_id>#chunk=<n>              文档切片
doc:<doc_id>#page=<n>               扫描件页码
doc:<doc_id>#ts=<start>-<end>       音视频时间戳
session:<session_id>#evt=<seq>      DSH 会话事件序号
url:<url>#<选中的文本片段 hash>      网页引用
```

这个字符串是**唯一**的定位方式，贯穿 chunk、记忆卡片、成果文件。它是 WPS 迁移时最值钱的抽象之一。

## 5. 核心数据模型

### 5.1 SQLite 派生索引

```sql
PRAGMA journal_mode=WAL;

CREATE TABLE doc (
  doc_id      TEXT PRIMARY KEY,        -- 来源派生，不是自增
  source_kind TEXT NOT NULL,           -- file|url|text|video|session|note
  source_ref  TEXT NOT NULL,           -- 绝对路径 | URL | 会话id#事件序号
  title TEXT, author TEXT, published_at TEXT, imported_at TEXT,
  mtime REAL, size INTEGER,            -- 增量短路用
  content_hash TEXT NOT NULL,          -- 内容变了才重新切片
  doc_hash     TEXT,                   -- 同内容不同路径 → 判定为重复
  status TEXT DEFAULT 'indexed',       -- pending|parsed|indexed|skipped|failed
  project TEXT, lang TEXT, summary TEXT,
  extractor TEXT, extractor_version TEXT
);
CREATE UNIQUE INDEX ux_doc_src ON doc(source_kind, source_ref);
CREATE INDEX ix_doc_hash ON doc(doc_hash);

CREATE TABLE chunk (
  chunk_id   TEXT PRIMARY KEY,
  doc_id     TEXT NOT NULL REFERENCES doc(doc_id) ON DELETE CASCADE,
  ordinal    INTEGER NOT NULL,
  heading_path TEXT,                   -- 章节路径，切片时带上
  text       TEXT NOT NULL,
  page       INTEGER, ts_start REAL, ts_end REAL,   -- 来源定位
  char_start INTEGER, char_end INTEGER,
  content_hash TEXT NOT NULL
);

-- 内容化 FTS：snippet()/highlight() 只有内容化才能用（实测确认）
CREATE VIRTUAL TABLE chunk_fts USING fts5(
  text, chunk_id UNINDEXED, doc_id UNINDEXED, tokenize='trigram'
);

CREATE TABLE memory (
  mem_id TEXT PRIMARY KEY,             -- (scope,kind,slug(topic)) 派生 → 同题不新建
  scope TEXT NOT NULL,                 -- user|project
  kind  TEXT NOT NULL,                 -- profile|project|decision|session|preference|goal
  title TEXT NOT NULL, body_path TEXT NOT NULL,
  project TEXT, tags TEXT,
  status TEXT DEFAULT 'active',        -- active|superseded|expired
  confidence TEXT,                     -- fact|summary|inference|unverified
```

### 5.3 七个设计问题的回答

**Q1 原始资料 / 整理后的知识 / 个人记忆怎么区分？**
三层物理分离：只读的 `source_ref` 指针（从不进仓库、从不被移动）、`data/docs/*.json` + `cache/`（解析派生物，机器生成可重建）、`data/memories|projects|decisions`（人的结论）。
判定规则一句话：**能被外部事实推翻的是资料，来自你的判断的是记忆。**

**Q2 如何避免同一件事反复写入？**
`mem_id` 由 `(scope, kind, slug(topic))` **派生**而非随机生成 → 同主题天然落到同一文件。写入前强制检索，命中相似则走 merge（追加或修正），而不是 create。

**Q3 如何更新旧结论并保留历史？**
不可变历史 + 可变指针。旧的写 `status: superseded` + `superseded_by`，新的写 `supersedes`；文件不删不覆盖，每次变更在 `## 修订历史` 追加一行。

**Q4 如何避免每次启动重扫全部资料？**
三级短路：`state/seen.json` 先比 mtime+size → 只有变了才算 hash → 只有 hash 变了才重新切片 → 只有 chunk hash 变了才动 FTS。
**启动只做 O(1) 读 seen.json，绝不在启动时遍历全盘**；扫描是显式动作（`recall.py add <dir>`）。

**Q5 如何让换模型 / 移植 WPS 不必推翻数据结构？**
- core 层只依赖 stdlib + sqlite3，不 import 任何宿主持有物
- 存储访问全走 `store.py` 适配器接口
- 权威数据是 Markdown/JSON，任何平台可读
- ID 是来源派生的稳定字符串，不依赖宿主自增
- LLM 调用点收敛到少数函数，接口就是"文本进文本出"
- **不把 DSH 的 `ctx.storageDomain` 当权威存储**

**Q6 如何备份、恢复、处理索引损坏？**
- 备份：`data/` 是纯文本，复制即备份
- 重建：删掉 `index/` → `recall.py index --rebuild` 从 `data/` + `cache/` 重放
- 体检：`doctor` 动词校验 schema 版本、孤儿 chunk、FTS 与 docs 计数一致性、seen.json 与磁盘差异
- 热备：SQLite `VACUUM INTO`

**Q7 如何限制检索结果，避免无关资料挤占上下文？**
硬预算 + 分级展开：
- 召回 top-40 → 过滤 → 去重（同 doc 最多 3 chunk）
- 默认**只返回 ≤240 字 snippet 的候选表**，总预算 ≤2500 token
- 只有明确 `--deep <chunk_id>` 时才取全文（≤8000 字/片）

## 7. 迁移兼容方案

### 7.1 能力三分

| 层次 | 包含内容 | DSH 侧形态 | WPS 侧形态 |
|---|---|---|---|
| **通用核心** | 指纹与去重 · 中文切片 · FTS5 召回与排序 · 记忆合并与 supersede · 来源定位符 · 上下文预算组装 · 成果模板 · schema 版本迁移 | `brain/core/` 纯 Python，只依赖 stdlib + sqlite3 | **直接复用，一行不改** |
| **Harness 适配** | 会话转录读取 · 记忆插件互通 · `.dsh/skills` 发现 · schtasks / dsh headless 定时 · `DSH_*` 环境变量与路径解析 | `brain/adapters/dsh/` | 不搬，换成 WPS 对应实现 |
| **WPS 适配** | `SKILL.md` 触发词与场景路由 · 文件来源（云文档/本地目录）· 持久化位置 · 定时能力 · 阻塞操作的 subprocess 隔离 | 本轮不实现 | 按届时官方规范逐项重写 |

### 7.2 已从公开资料看到、但必须当成"未验证"的 WPS 事实

来源：[灵犀Claw Skill 开发实战](https://bbs.wps.cn/topic/91400)、[灵犀技能开发半年实战总结](http://bbs.wps.cn/topic/88835)（社区文章，**非官方规范**）。

- 灵犀 Skill 是 `SKILL.md` + `scripts/` + `references/` 结构；官方有 `skill-creator` 提供 init/package
- Skill 会占用上下文窗口，需渐进式披露（核心流程在 SKILL.md，细节放 references/ 按需加载）
- **有持久化 Python 环境**；任何 COM / 批量操作必须 subprocess 出去，否则会锁死环境
- 案例中有人索引了 170GB 本地素材库（**暗示**有本地 FS 访问，但未证实）

必须届时逐项验证的：本地路径访问范围、SQLite 可用性与写入位置、跨会话持久状态、定时触发能力、网络调用权限。

### 7.3 为迁移做的 7 个具体决定

1. core 零宿主依赖（只 stdlib + sqlite3）
2. 权威数据纯文本（Markdown / JSON），WPS 端可直接读写
3. 单一 CLI 入口，宿主只需"会执行一条命令"
4. LLM 调用点收敛到 2 个函数，接口 `(prompt) -> text`；DSH 侧由 Agent 本体承担，WPS 侧接平台模型
5. 路径全从 `brain.config.json` + 环境变量读，**绝不硬编码 `C:\Users\<你>`**
6. **不把 DSH 专有的 `ctx.storageDomain` 当权威存储**
7. `SKILL.md` 拆两层：薄的（宿主相关）+ `references/*.md` 厚的（宿主无关）

## 9. 附录：本轮排查的三个故障

### 9.1 `document_to_image` 不可用 → 已修复并端到端验证

**根因**：`picturereader` 把上游作者的机器路径写死成默认值。

- `picturereader/src/doc-tools.js:40`：
  `const DOC_VENV_PY = process.env.DSH_DOC_PYTHON ?? 'C:\\Users\\<某用户>\\doc_venv\\Scripts\\python.exe';`
- 同插件 `scripts/setup-doc-venv.mjs` 也硬编码了 `C:\Users\<某用户>\...`

换用户必然 ENOENT。且该常量**在模块加载时读取一次**，所以修好后必须重启 DSH 才生效。

**修复动作**：
1. 用 anaconda 3.13.9 建独立 venv：`C:\Users\<你>\.dsh\doc_venv`
2. 装入 PyMuPDF 1.28.2（走 §9.3 的离线流程）
3. 设用户级环境变量 `DSH_DOC_PYTHON=C:\Users\<你>\.dsh\doc_venv\Scripts\python.exe`
4. **端到端验证**：直接跑插件自己的 `scripts/doc-to-image.py <pdf> <out> probe 150 1`，成功产出 `1241×1754`、132KB 的 PNG

**回滚**：
```powershell
[System.Environment]::SetEnvironmentVariable('DSH_DOC_PYTHON',$null,'User')
Remove-Item -Recurse -Force "C:\Users\<你>\.dsh\doc_venv"
```

**剩余缺口**：LibreOffice 未安装 → `Office → PDF → PNG` 这一段仍不通。纯文本抽取不需要它（DOCX 用 zipfile+lxml，PPTX 用 python-pptx，都已实测）。

### 9.2 `memory_search` 报 "not lossless JSON" → 已精确定位

**旧结论**（记录在案的）：任何 query 都失败。
**本次精确定位**：

| 查询命中范围 | 结果 |
|---|---|
| 仅 project scope（`aphelion` / `cloudflare`） | ✅ 正常返回 JSON |
| 含 user scope（`memory` / `夸克` / `dsh-memory` / `内核版本` / `0.2.0-rc.2`） | ❌ 必定失败 |
| `memory_list`（双域） | ✅ 正常 |
| `memory_read` | ✅ 正常 |

**推断原因**：user 记忆没有归属工作区，结果对象里带了一个值为 `undefined` 的字段（如 `workspace`）；`JSON.stringify` 会丢掉 undefined 属性，往返后对象不等价，被判定为"非无损 JSON"。project 记忆有 workspace 字符串，所以没事。

**绕过**：`memory_list` + `memory_read` 双域都正常，可替代；或自建索引直接读同一批 Markdown。

**设计结论**：**不要把 RecallOS 的记忆核心建立在这个插件上。** 它只做大小写不敏感的子串匹配，没有来源定位、没有版本、没有 supersede。插件保留作"系统提示注入通道"。

**存储布局**：用户级 `~/.dsh/memory/`（`MEMORY.md` 索引 + `memories/`）；项目级 `<project-root>/.dsh/memory/`（有 `.dsh/memory` 标记或 VCS 根即可）。

### 9.3 pip 安装被 Windows 注册表代理卡死 → 已找到稳定解法

**症状**：`pip install` 报 `ProxyError('Cannot connect to proxy.')`，重试 5 次后失败。

**根因**：Python 的 `urllib.request.getproxies()` 在 Windows 上**读 WinINET 注册表**（`HKCU:\Software\Microsoft\Windows\CurrentVersion\Internet Settings`），而不是只看环境变量。所以清空 `HTTP_PROXY` / `HTTPS_PROXY` 无效。更麻烦的是代理本身时通时不通：同一分钟内代理直连同一 URL，一个 000（16 秒超时）、一个 200（2.1 秒）。

**可靠解法（已验证）**：

```powershell
# 1. 查真实 wheel 文件名
curl.exe -s --noproxy "*" https://pypi.org/pypi/<pkg>/json
# 2. 直连下载（保存的文件名必须是真实 wheel 名，pip 会校验）
curl.exe -s -L --noproxy "*" -o "<pkg>-<ver>-cp310-abi3-win_amd64.whl" "<url>"
# 3. 离线安装
python -m pip install --no-index --no-deps --force-reinstall "<pkg>-<ver>-cp310-abi3-win_amd64.whl"
```

**两个必踩的点**：
1. `pip install --proxy ""` 在 PowerShell 里会被引号处理搞坏参数（实测把 `--retries` 的值吃成了包名）
2. **保存的 wheel 文件名必须完整合法**，存成 `pymupdf.whl` 会报 `Invalid wheel filename (wrong number of parts)`

**另外**：本机 `pwsh` 实际是 PowerShell **5.1**（不是 7），`?.`、`-Out-String` 这类 7 的语法/参数会直接报错。`Get-ChildItem env:` 在本机也会因重复键抛异常，改用 `[System.Environment]::GetEnvironmentVariables()`。
