### ❌ 没有 / 做不到

**1. 电脑不会"按意思"找东西**（这是唯一真正重要的缺口）

你搜"那个讲大脑怎么记东西的"，它找不到标题写着"记忆机制"的文件——它只会逐字比对。

> **解决办法**：让电脑先按字找出 40 个"最像的"候选，然后**我来读这 40 个**，判断哪些真的相关。反正每次都是我帮你干活，让我当这个"语义层"，不额外花钱、不额外装东西。
>
> 这个方案还有个好处：将来搬到 WPS 也一样能用，因为不依赖任何特殊能力。

**2. 没装 Office 转 PDF 的工具**（影响很小）
只影响"把 PPT 转成图片给 AI 看"这条路，**不影响提取文字**。

**3. 我没法自己设置定时任务**
DSH 虽然带了定时功能，但没开放给我。得用 Windows 自带的任务计划来替代。

**4. 记忆搜索功能有 bug**（详见下一节，有绕过办法）

## 三、我修好 / 查清的 3 个问题

### 问题 1：PDF 转图片功能是坏的 → ✅ 已修好

**表现**：一用就报"Python 环境缺失，请先运行 setup 脚本"。

**原因**：写这个插件的作者，把**自己电脑的路径硬编码**进去了——`C:\Users\<某用户>\doc_venv`。你的电脑上没有这个文件夹，所以永远找不到。

**我做了什么**：
- 在你的目录 `C:\Users\<你>\.dsh\doc_venv` 建了一个干净的小环境
- 装上了需要的库（PyMuPDF）
- 然后**用插件自己的脚本，跑了一份真实 PDF，成功生成了 1241×1754 的图片**

**还差最后一步**：需要**重启一次 DSH**，插件才能读到新设置。

**如果将来想撤销**：删掉那个文件夹 + 清掉环境变量 `DSH_DOC_PYTHON` 就行，不留痕迹。

---

### 问题 2：记忆搜索有 bug → ✅ 找到确切原因

**表现**：搜索记忆时报错 `value is not lossless JSON`。

**我发现的规律**（比之前记录得更准确）：

| 操作 | 结果 |
|---|---|
| 搜**项目记忆**（如搜 "aphelion"） | ✅ 正常返回 |
| 搜**个人记忆**（如搜 "夸克"） | ❌ 必定报错 |
| 列出记忆（两种都列） | ✅ 都正常 |

**原因**：个人记忆不属于任何项目，返回结果里带了一个"空值"字段，序列化时被丢掉了，宿主就判定格式不对。

**绕过办法**：用"列出 + 读取"代替"搜索"，现在立刻能用；或者我们自建索引直接读那些文件——**反正我们本来就要自建索引**。

**为什么这事重要**：这说明**不能把 RecallOS 的记忆核心建立在这个现成插件上**。它只能做逐字比对，没有来源标注、没有版本管理。插件保留当"开机自动提醒我"的通道就好。

---

### 问题 3：装软件被网络卡死 → ✅ 找到稳定解法

**表现**：Python 装库时反复报 `Cannot connect to proxy`，重试五次后失败。

**原因**（挺坑的）：
- Python 装库时会自动走系统代理，而那个代理本身时好时坏（同一分钟内，走代理失败、直连成功）
- 更坑的是，它读的是 **Windows 注册表**里的代理设置，所以你把环境变量清空也没用

**解法**：绕过代理直连下载，再离线安装。已经实测成功——上面那个 PDF 库就是这么装上的。

**顺带发现**：保存文件名必须完整合法（存成 `pymupdf.whl` 会被拒绝，必须叫 `pymupdf-1.28.2-cp310-abi3-win_amd64.whl`）。这种坑不记下来，下次还要重踩。

## 四、这个系统长什么样（用图书馆打比方）

想象你的电脑里要建一座**私人图书馆**：

```
     你的资料（只读，绝不搬动）
  桌面 PPT / Word / PDF / 笔记 / 聊天记录 / 网页
                    │
                    ▼
            【整理员】解析 + 切块 + 编目
                    │
         ┌──────────┴──────────┐
         ▼                     ▼
    【原书区】              【卡片柜】
     data/                index/recall.db
   人能直接读的           电脑查得飞快
   Markdown / JSON        坏了随时能重建
         │
         ▼
   【读书笔记区】
   你的画像 · 项目记忆 · 决策记录 · 历史对话摘要
         │
         ▼
   【图书管理员】 = 我
   你提需求 → 我先查卡片柜 → 挑出相关的 →
   读原书 → 给你一份**标着出处**的成果
         │
         └──→ 成果存回原书区，下次还能被搜到
```

**三个关键设计：**

1. **原书永不搬动** —— 只建立索引，不移动、不改名、不删除你的任何文件
2. **卡片柜随时能重建** —— 哪怕搜索数据库彻底坏了，删掉重建就行，资料一份都不会丢
3. **成果必须带出处** —— 每份生成的东西都标注"这句话来自哪份资料的哪一段"

## 五、文件夹长什么样（简化版）

```
recallos/                        ← 项目文件夹
│
├─ .dsh/skills/recallos/         ← 技能入口
│   └─ SKILL.md                      （DSH 规定必须放这个位置，放别处不生效）
│
├─ bin/recall.py                 ← 唯一命令入口，所有操作都从这里进
│
├─ brain/                        ← 代码
│   ├─ core/                        通用逻辑（将来搬去 WPS 能直接用）
│   ├─ adapters/dsh/                DSH 专用部分（将来要重写）
│   └─ ingest/                      各种格式的解析器
│
├─ data/                         ★ 你的数据，纯文本，复制即备份
│   ├─ profile.md                   你的画像
│   ├─ memories/                    记忆卡片，一卡只记一件事
│   ├─ projects/                    每个项目一个文件夹
│   ├─ decisions/                   决策记录（含"这个决定推翻了哪个旧决定"）
│   ├─ sessions/                    历史对话摘要
│   ├─ docs/                        每份资料的档案
│   ├─ topics/                      主题页（把这个主题下的资料串起来）
│   └─ outputs/                     生成过的成果（带出处）
│
├─ index/recall.db               ← 【可随时删】搜索索引
├─ state/                        ← 进度记录（防止每次重新扫描全部资料）
└─ tests/                        ← 自动测试
```

**最重要的一行**：`data/` 里全是纯文本，**你随手复制一份就是完整备份**；`index/` 删了也不要紧。

## 六、分 6 步做，每步都能验证

| 步骤 | 做什么 | 怎么算成功（不靠我"说成功了"） |
|---|---|---|
| **P0** | 搭骨架 + `doctor` 自检命令 | 空库时自检通过；建库后文件真实存在 |
| **P1** | 导入：MD / TXT / Word / PPT + 防重复 | 导入 4 份 → 硬盘上确实多出 4 个档案；**再导入一次，数字一个不变** |
| **P2** | 搜索 + 结果长度控制 | 搜"复习资料"能搜到并高亮；返回内容 **< 2500 字**（防止塞爆我的记忆） |
| **P3** | 历史对话入库 | 13 个对话 → 生成对应数量的摘要文件；再跑一次不重复生成 |
| **P4** | 生成成果 + 出处回写 | 生成的文件真实存在；里面的每个出处都能回查到原资料 |
| **P5** | 记忆系统（画像 / 项目 / 决策） | 同一件事记两次 → **只产生一个文件**，旧版本不删、留痕 |

**每一步都有一个共同铁律**：完成前必须跑 `recall.py doctor` 且自检通过，自动测试全绿。测试检查的是**硬盘上的文件和数据库里的行**，不靠我口头说。

## 八、我的建议：第一步做什么

### 先做「存进去 + 找得到」这一件事，别的都往后放

**用大白话说理由**：如果东西存不进去、存进去又找不着，那后面所有花哨功能都是空中楼阁。这一步是整个项目的地基，而且**技术风险最低**（我已经实测跑通了），但**立刻有用**——直接解决"我忘了文件放哪"这个最痛的点。

### 怎么证明它真的可用（三条硬指标）

1. **导入 3 份真资料** → 硬盘上确实多出 3 个档案文件，数据库里确实有内容
2. **再导入一遍** → 数据库里的数字**一个都不变**（证明不会重复膨胀）
3. **把 `index/` 整个删掉** → 一条命令重建 → 用同一个关键词搜，结果和删之前**一模一样**（证明索引不怕坏）
4. **关掉终端重新打开** → 再搜一次，结果还是不变（证明真的存住了）

这四条全部是机器可自动检查的，**没有一条需要我"说成功了"来证明**。
