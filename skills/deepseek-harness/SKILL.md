# RecallOS

个人 AI 外接大脑。核心命题：**你不必记得自己保存过什么，AI 会在需要时找到相关资料，并帮你用起来。**

<!-- recallos:where:begin -->
> ⚠️ 这一段本该由 `install-skill` 写入 RecallOS 在**本机**的绝对路径。你看到这句话，
> 说明这份技能是**手工复制**进来的（`install-skill` 没跑过），所以技能并不知道仓库在哪。
> 按「第 0 步」的兜底处理，**不要**假装工具存在，也不要让用户去找目录。

## 第 0 步：先确认工具真的在这台机器上（每次会话一次）

用上面**「本机位置」**里给出的那条绝对路径命令，加 `--version` 跑一次：

- 输出 `recallos <版本号>` → 工具在，继续往下走。
- 报「文件不存在 / No such file / 无法识别」→ **工具没装好**。这时唯一正确的
  回答是一句话加一条能照抄的命令，而不是让用户去找目录：

  > 「RecallOS 的命令行还没装在这台机器上。两行就能装好：
  > `git clone https://github.com/Rui626626/Recallos.git`，
  > 然后 `cd Recallos` 并 `python bin/recall.py install-skill --user`。
  > 装完告诉我一声。」

**这一条是本项目最贵的教训。** 真实发生过的故障：用户下载之后，AI 读到的是技能
说明、却找不到 `bin/recall.py`，于是回答「库还没初始化，请给我一个目录」——
把一个**能修的安装问题**伪装成了**需要用户配合的检索问题**，用户拿到的是
一个永远不会有结果的追问。所以：**先说清工具在不在，再谈搜什么。**

## ⭐ 检索范围：问一次、记住，之后一句话就搜

**前提：第 0 步已经通过。**

铁律是「**不静默扫盘**」，不是「每次检索前都问用户目录」。后者是自相矛盾的：
用户说得清目录，就说明他知道文件在哪 —— 那还要这个工具干什么？工具的用途恰恰是
**他不想记得**。真实发生过的失败对话就是这样：

> 用户：「帮我找简历」　AI：「请告诉我简历在哪个文件夹」　用户：……

所以流程只有三步，而第 2 步**一辈子只做一次**：

1. **先看有没有授权过范围**：
   ```
   python "<入口>" scope show
   ```
2. **如果范围是空的，问一次**，一句话就够，别写成问卷：
   > 「我可以先在你电脑的 `Documents`、`Desktop`、`Downloads` 里找。要这么做吗？」

   得到同意后执行（它只记录**真实存在**的目录）：
   ```
   python "<入口>" scope default
   ```
   用户想指定别的位置：`python "<入口>" scope set "<目录>"`。
   授权写进 `brain.config.json`，**以后不用再问**。
3. **之后每次都直接搜，不要再问路径**：
   ```
   python "<入口>" search "简历"
   ```
   空库也能搜：索引为空时 `search` 会自动在已授权范围里**现场搜**，
   不需要 `init`、不需要 `add`。

**绝对不要做的三件事：**

- **已经授权过范围，还问「文件在哪个文件夹」** —— 那等于承认这个工具没用。
- **说「库是空的，所以我没有可搜的对象」** —— 现场模式不读索引，空库不是阻塞理由。
- **绕开 scope 去扫范围之外的地方**。`--in <目录>` 只在用户**当场点名**时用。

范围之外的目录，代码永远不会读——这一点可以放心答应用户。
没授权时 `search` 会明确拒绝并给出三条路，照它的提示走就行。

## 用法

所有命令都用**「本机位置」里那条绝对路径**，不需要 `cd`，也不需要猜仓库在哪。
下面把入口写成 `<入口>`（它是一个带尖括号的**占位符**，必须替换成「本机位置」里
那条真实的 `"<仓库>/bin/recall.py"`）。**不要**把它写成 `python bin/recall.py`
这种相对路径——那个基准目录不存在，抄过去就跑不起来，而跑不起来的后果就是 AI
说「工具还没装」。
Windows 上先设一次 `$env:PYTHONIOENCODING="utf-8"`，否则中文输出会乱码。

```powershell

python "<入口>" doctor                       # 先自检
python "<入口>" scope default                # 一次性授权常用目录（只做一次）
python "<入口>" scope show                   # 看当前授权了哪些目录
python "<入口>" install-skill --user         # 让 DSH 认识它（只需一次）
python "<入口>" search "查询" --in "某目录"    # 零设置：不建库直接搜
python "<入口>" add "某个文件夹"               # 导入（只读，绝不改动原文件）
python "<入口>" search "通货膨胀"              # 检索
python "<入口>" search "通货膨胀" --explain     # 看每一段召回了多少
python "<入口>" search "复习资料" --render      # 带 locator 的 markdown，可回查
python "<入口>" compose "通货膨胀" --kind review  # 汇编成带出处的成品
python "<入口>" verify artifacts/*.md         # 回查成品里每个出处
python "<入口>" memory remember "用户偏好简洁回答" --topic "回答偏好"
python "<入口>" memory expire "过时的结论"      # 默认搜不到，--include-expired 能搜到
python "<入口>" archive "会话目录或文件"         # 对话记录入库
python "<入口>" alias learn                  # 从正文里学「中文（English）」对照
```

**重要**：能搜到哪里，**只由 `scope` 决定**（它存在 `brain.config.json` 的 `roots`）。
没有授权过就是空数组——这时候**不要**扫描任何目录。用户同意授权之后，检索范围就是
那几条路径，范围之外不读。`add` / `archive` 另说：它们会**导入**内容，所以只接受
用户当场给出的路径，不要拿 scope 去批量导入历史对话——对话记录属于隐私内容，要等用户点名。

## 检索能力（务必如实描述）

`search` 分四段，每段都能解释自己贡献了什么（`--explain` / `--json` 的 `stages`）：

1. **精确短语** —— 原样相邻出现，置信度最高
2. **别名扩展** —— 「菲利普斯」→「phillips」这类跨语言/跨叫法的等价
3. **模糊 OR** —— 拆成探针词，任一命中即召回，容**错别字**与**少字多字**
4. **相似度重排** —— 用覆盖率把第 3 段召回里的噪声丢掉（阈值动态）

**能做到**：错别字（`通或膨胀` → 通货膨胀）、少字（`基尼` → 基尼系数）、
中英互指（`菲利普斯` → 只有英文标题的 `the Phillips curve`，靠别名表）、
**拼音搜索**（`tonghuopengzhang` → 通货膨胀）、**同音容错**（`直接水` → 直接税）、
**搜文档标题与小标题**（索引文本 = 标题 + 标题路径 + 正文 + 拼音连写）。

**做不到（明确的取舍，不是 bug）**：
- **没有语义检索**。同义词、上下位关系（「通胀」↔「物价上涨」）只能写进 `aliases.json`。
  **同音**能容错，**同义**不能。
- 文档里一个汉字都没有的英文笔记，统计方法**无解**；拼音也帮不上——拼音表里没有
  那几个字，因为文档里根本没有它们。只能靠别名表。
- 不做分词、不做 OCR、不改动原文件。
- **`compose` 不写结论**。它是汇编器不是作者：正文全部来自原文，结论小节留空给
  Agent 或人补写。不要替它编造未出现在出处里的内容。

## 铁律（写在这里，因为每条都踩过）

1. **原始文件只读。** 永不移动、改名或删除用户的任何资料，只建立索引。
2. **`data/` 是权威，`index/` 是派生物。** 索引随时可删可重建；用户数据绝不能只存在于索引里。
   `aliases.json` 与 `data/memory/` 同理——都有测试守着「索引删掉后数据仍在」。
3. **失败必须留痕。** 任何失败的导入/转换都要有一行记录和具体原因，不允许静默跳过。
4. **不把没实现的功能报告为通过。** `doctor` 用独立状态区分通过 / 警告 / 未实现。
5. **一切断言落在真实文件与数据库行上**，不接受「模型说成功了」。
6. **检索结果必须带出处。** 每条命中都有 `locator`（`doc:<id>#h=<hash>@<序号>`），
   引用时不写 locator 等于不可核查；成品写完立刻用 `verify` 自查。
7. **返回内容有预算上限**（默认 2500 tokens），被裁掉的条数明确报出来。

## 改代码时必须知道的三件事

1. **改了「写进 FTS 表的内容」就要 bump `INDEX_CONTENT_VERSION`**（`brain/core/versions.py`）。
   漏掉这一步的后果是：老索引不重建，而且**不会报错**——它会安静地少返回东西。
   这是本项目最危险的一类 bug。已发生的实例：原来只索引正文，导致「搜文档自己的标题
   返回空」，版本戳从 `ch1` 提到 `ch2` 才自动修好；加拼音投影时提到 `ch3`。
2. **索引写入与阈值判定必须用同一个投影函数**（`pinyin.indexed_projection`）。
   曾经写入用拼音版、判定用原始正文版，结果拼音召回了候选却被阈值全部否掉，
   表现为「明明召回了却返回空」。
3. **`REQUIRED_DIRS` 只有一个来源**（`brain/cli/init.py`），`doctor` 从那里 import。
   曾经复制过一份，结果两边数字对不上（doctor 报 6 个、init 建 8 个）。
4. **覆写整个文件前先读它。** 这条不是客套：开发中因为覆盖 `SKILL.md` 时丢了
   frontmatter，`recallos` 直接从技能目录里消失过一次。

## 通用事实（对所有机器成立）

- **项目根 = 含 `bin/recall.py` 与 `brain/` 的那个目录。** 本机的确切路径写在
  上面「本机位置」里（`install-skill` 写入）；`doctor` 的第一行也会打印它。
  技能被复制到技能根之后**已经不在仓库里**，所以「本文件所在目录」不能当仓库用。
- **Skill 入口放哪**：DSH 用「向上找 `.git`，找不到就用 cwd」确定项目根，技能放在
  `<项目根>/.dsh/skills/<名字>/SKILL.md`。所以：仓库**自己有 `.git`** 时，入口放在
  仓库**内部**；仓库**没有 `.git`** 时，入口放在工作区里、仓库的**旁边**。
- 中文检索有两条通道：`trigram`（≥3 字）与逐字索引（2 字查询靠它）。模糊层在它们之上。
- 索引的可检索文本 = **标题 + 标题路径 + 正文 + 拼音连写**。改这段内容必须 bump
  `INDEX_CONTENT_VERSION`，否则老索引不会重建，而且**不会报错**。
- 拼音表随包发布（`brain/data/pinyin.tsv.gz`），不依赖任何第三方库。删掉它即降级。
- `brain.config.json` 的 `roots` **就是** scope：默认为空 = 什么都不扫；
  授权之后只在这些目录里找，范围之外代码不会读（同一条事实只存这一处）。

## 本机事实（⚠️ 换机器时请替换本节，不要照搬）

> 以下是**这一台机器**实测到的环境，仅供排查参考。换机器请用 `doctor` 重新确认。

- Windows；`pwsh` 是 Windows PowerShell **5.1**（不是 PowerShell 7）
- Python 3.13.9（Anaconda）；SQLite 3.51.0 带 FTS5
- **`.ps1` 脚本要带 UTF-8 BOM**：PowerShell 5.1 在无 BOM 时按 ANSI 解码，中文会乱码。
  `install.ps1` 因此正文用英文并带 BOM。
- **DSH 会话文件是多个 zstd frame 顺序拼接的**，必须用 `stream_reader` 读到底；
  用 `.decompress()` 只会拿到第一帧然后**静默截断**（`archive` 里有回归测试守着）
- Python 读的网络代理来自 Windows 注册表，清空环境变量无效；装包要用
  `curl --noproxy "*"` 直连下载后离线安装
